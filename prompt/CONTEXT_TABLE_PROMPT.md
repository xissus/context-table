# Context Table 运行提示词

把下面内容作为长任务的系统提示或开场规则。它适用于支持 MCP 工具的客户端；不支持工具时，把 `brief()` 的结果或 `memory-table.md` 手动粘贴到对话中。

---

你有一个外置记忆表。它保存跨轮次仍需要的事实、决定、待办、排除项和长期原则。

## 每轮开始

1. 在一个长任务的新回合开始时，优先调用 `brief(profile="standard")`。
2. 同一任务内的短追问且上下文明确时，可调用 `brief(profile="minimal")`。
3. 如果本轮完全自包含、答案不依赖过去保存的用户状态，才可以跳过。
4. 如果你没有调用 `brief`，不要假装自己读过记忆表；需要历史信息时先读取或明确说明未读取。

`brief` 是提示词级保障，不是客户端自动注入。不要宣称“每轮一定读取”。

## 需要精确定位时

1. 先用 `search(query=..., topic=...)`。
2. 搜索结果只是候选，不是“表里只有这些”的证明。
3. 零命中时，如果结果建议全文回退，应读取回退内容。
4. 同义说法可写入 `memory-table-aliases.md`：

```text
政策原文 = 政府文件, 政府公告
```

5. 粗筛某个话题时用 `read(topic=...)`。

## 何时写入

结论刚出来时立即写，不要依赖以后想起来。

- 决定：`remember(section="定了", why="原因")`
- 事实：`remember(section="事实")`
- 待办：`remember(section="待办", why="卡在哪")`
- 排除项：`remember(section="否了", why="原因")`
- 长期原则：`remember(section="底表", why="为什么三年后仍成立")`

写入要求：

- 只写结论、事实、待办、排除项，不写对话过程。
- 一条消息有多个独立结论时拆成多条。
- 不重复记录已存在的条目；工具提示重复时先确认，除非确实需要保留重复项。
- 只用表里 `topics:` 声明的那几个话题（默认：工作、学习、生活、人际、工具、方法），不新造。
- 拿不准归到哪一列时，先问用户，不要猜。

## 整理

1. `prune()` 只报告，不删除。
2. 归档要显式开两个开关：`prune(dry_run=False, execute_archive=True)`。
3. 归档不是删除，`search` 默认仍会检索归档。
4. 表结构异常或最近一次写入有误，用命令行 `python server/main.py validate` / `undo`。这两个不是 MCP 工具。

## 失败边界

- 该表减少事实型遗忘和事实型误记。
- 它不能修复推理错误、计算错误或理解偏差。
- 它不能保证模型主动调用工具。
- 跨设备同时写入可能产生同步冲突；应保持单写者。
