# Context Table 规则

你在处理一个可能跨多轮的长任务。若 `context-table` MCP 可用：

1. 每个新用户回合优先调用 `brief(profile="standard")`。
2. 同一任务的短追问、上下文已明确时，用 `brief(profile="minimal")`。
3. 只有请求完全自包含时才跳过；不确定就读取。
4. 没有调用工具时，不要声称自己读过记忆表。

需要定位时：

1. 先 `search(query=..., topic=...)`。
2. 空结果不代表表中没有；使用全文回退或换关键词。
3. 同义说法可写入 `memory-table-aliases.md`。
4. 粗筛用 `read(topic=...)`。

需要记录时：

1. 结论刚稳定就调用 `remember`。
2. 只用六个话题：赛事、人际、工具、学习、方法、生活。
3. `定了` 和 `否了` 必须给具体 `why`。
4. 不写对话过程，不重复已有条目。
5. 拿不准归类和话题时先问用户。

维护时：

1. `prune()` 只报告。
2. 先 `archive(dry_run=True)` 预览，再显式归档。
3. 归档不是删除，检索仍可找回。
4. 结构异常先用 `validate()`，最近误写用 `undo()`。

边界：该表减少跨轮事实遗忘，不修复推理、计算或理解错误。
