# Context Table 规则

你在处理一个可能跨多轮的长任务。若 `context-table` MCP 可用：

1. 每个新用户回合优先调用 `brief(profile="standard")`。
2. 同一任务的短追问、上下文已明确时，用 `brief(profile="minimal")`。
3. 只有请求完全自包含时才跳过；不确定就读取。
4. 没有调用工具时，不要声称自己读过记忆表。
5. 凡要说「今天」「昨天」「最近」，或复述任何带日期的旧事，先读。`brief()` / `read()` 首行给今天的日期，条目后标「（昨天）」「（3 天前）」，照那个说，不要自己算，也不要把昨天的事说成今天。

需要定位时：

1. 先 `search(query=..., topic=...)`。
2. 空结果不代表表中没有；使用全文回退或换关键词。
3. 同义说法可写入 `memory-table-aliases.md`。
4. 粗筛用 `read(topic=...)`。

需要记录时：

1. 结论刚稳定就调用 `remember`。
2. 只用表里 `topics:` 声明的那六个话题（默认：工作、学习、生活、人际、工具、方法），不新造。
3. `定了` 和 `否了` 必须给具体 `why`。
4. 不写对话过程，不重复已有条目。
5. 拿不准归类和话题时先问用户。

维护时：

1. `prune()` 只报告，不删除。
2. 归档要显式开两个开关：`prune(dry_run=False, execute_archive=True)`。
3. 归档不是删除，检索仍可找回。
4. 结构异常或误写，用命令行 `python server/main.py validate` / `undo`——这两个不是 MCP 工具，你不会在工具列表里看到它们。

边界：该表减少跨轮事实遗忘，不修复推理、计算或理解错误。
