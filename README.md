# Context Table

> **一张能手动改的状态表。不是记忆工具。**

不跑服务、不建索引、不调模型、不装依赖。
一个 Markdown 文件，五张表，改坏了用记事本修。

别的方案给你一个服务，这个方案给你一个文件。

---

## 为什么做这个

### 一个人不会只用一个 AI

| 工具 | 价格 | 用来干什么 |
|---|---|---|
| ChatGPT / Codex | $20–500/月 | 重活、要质量的活 |
| Claude Code | $20–200/月 | 长上下文、写代码 |
| DeepSeek | 几块钱/百万 token | 便宜、够用 |
| WorkBuddy | 免费额度 | 日常小活 |

**价格差 100 倍，能力也差几档。** 用一个工具包办所有事，等于要么花冤枉钱，要么干不好活。

所以多工具并用不是偏好，是**成本结构逼出来的**。

### 但它们的记忆互不相通

- ChatGPT 记得你在 ChatGPT 里说过什么
- Codex 记得你在 Codex 里做过什么
- **它们不知道对方存在**

换一个工具，你要把之前说过的再解释一遍。**项目越长，这个成本越高。**

平台不会解决这件事——没有一家有动力把记忆交给竞品。

## 跟“记忆工具”有什么不同

| | 笔记类（Obsidian、Notion、Basic Memory） | Context Table |
|---|---|---|
| 结构 | 自由，自己建 | **固定四列 × 五张表** |
| 模型要想的 | 该写什么、写到哪、怎么关联 | **这条归哪列** |
| 存的 | 我知道什么 | **我现在到哪一步** |
| 检索 | 全文 / 向量 / 图谱 | 全读（表小时）或按话题 |

**结构自由是负担。** 面对一个空白笔记本，人会想“这该记吗、记成什么样”，结果是大部分人不记。

面对四列，人只想“这条是事实还是待办”。

**约束降低操作成本，操作成本决定这东西会不会被用第二次。**

## 已知的同类，以及我差在哪

这类工具已经不少。先把话说清楚，省得你装完才发现——

| 项目 | 它有的 | 我没有的 |
|---|---|---|
| [ai-memory](https://github.com/akitaonrails/ai-memory)（1.6 万 ★） | lifecycle hooks 自动捕获、git 版本、跨设备、团队共享 | **自动捕获** |
| [Basic Memory](https://github.com/basicmachines-co/basic-memory) | 自由 Markdown + 向量检索 + 知识图谱 | 语义检索 |
| [Twining](https://github.com/daveangulo/twining-mcp) | 记决策与被否方案，按 token 预算装配 | 自动相关性排序 |
| [Mem0](https://mem0.ai) / OpenMemory | 托管向量库，多设备同步 | 一切要联网的 |

**差得最狠的是第一行。** 它们能用 hooks 自动捕获会话，我这里靠模型自觉调工具——它可能漏。这是真实差距，不掩饰。

换来的是另一头：不跑服务、不建索引、出错能自己打开文件改、Windows 双击可用。

**简单不等于强。** 论功能，这份表打不过上面任何一个；论“零基础能不能用明白”，它赢。

## 五张表

| 表 | 收什么 | 必填 |
|---|---|---|
| **定了** | 做过的决定 | 日期、话题、决定、**为什么** |
| **事实** | 人名、数字、路径、时间 | 日期、话题、事实 |
| **待办** | 还没做的 | 日期、话题、做什么、**卡在哪** |
| **否了** | 讨论过但排除的 | 日期、话题、排除了什么、**原因** |
| **底表** | 三年后还成立的原则 | 加入日、原则 |

加粗的是必填——**原因比结论更值得留**。

话题默认六个：`工作` `学习` `生活` `人际` `工具` `方法`。

**不是硬规定。** 学生打比赛可以换成 `赛事`，上班可以换成 `会议` `同事` `交付`。
改 `CONTEXT_TABLE.md` 开头一行，或者设环境变量 `CONTEXT_TABLE_TOPICS=赛事,学习,生活,人际,工具,方法`。

为什么要限死个数：标签一自由，三个月后就是一团乱麻，等于没有。**换一套可以，别临时加第七个。**

## 用法

### 两条路，选一条

**A. 电脑上没装 Python** → 下 `context-table-win-x64.zip`（28MB，在 Releases），解压，双击 `install\install.bat`。

包里带着完整的 Python 运行时（3.13.9 + mcp 依赖），**你电脑上什么都不用装**。只支持 Windows x64。

**B. 已经有 Python 3.10+** → `git clone` 本仓库，双击 `install\install.bat`。

### 安装器会做这些

两条路跑的是同一个脚本，区别只在第 1 步：

1. 找 Python —— 便携版直接用包里自带的；源码版找本机的（PATH + 6 个常见位置），版本不够会直说
2. 缺 `mcp` 就自动装（便携版已内置，跳过这步）
3. 建表（带三条示例，看懂格式后删掉）
4. 写客户端的配置——已有的条目跳过，不覆盖；改之前先备份
5. 装规则文件（DSH 全局 + WorkBuddy 用户级）

只想看它会改什么：`install\install.bat -DryRun`。

### 我用的系统能装吗

服务本身是纯 Python，跨系统。差别只在“怎么把 Python 弄到手”：

| 系统 | 怎么装 | 要预装什么 | 状态 |
|---|---|---|---|
| **Windows x64** | 便携包，解压双击 | **什么都不用** | ✅ 实测 |
| **Windows x64** | 源码 + Python 3.10+ | Python | ✅ 实测 |
| **macOS** | 源码 + Python 3.10+ | Python | ⚠️ 没测过 |
| **Linux** | 同上 | Python | ⚠️ 没测过 |
| 任意 | 纯提示词版（`prompt/`） | 无 | ✅ 无依赖 |

**安装脚本只有 Windows 版。** Mac/Linux 手动配三行，见 [`ARCHITECTURE.md`](ARCHITECTURE.md#7-分发方式与平台支持)。

> Mac/Linux 那两行不是“支持”，是“应该能”——代码里文件锁写了两套实现
> （`fcntl` 和 `msvcrt`），但没在真机上跑过。跑通了欢迎说一声。

**然后手动两步**：重启三个客户端（豆包另算，要单独手点）；在 WorkBuddy 的连接器里给 `context-table` 点一次「信任」。

只有 WorkBuddy 要手点——MCP 首次连接必须由人确认。Codex 和 DSH 不用点任何东西。

> DSH 的 `@deepseek-ai/dsh-mcp-client` 随应用自带，**不需要安装**。往 profile 里 `pnpm add` 反而会挡住内置版本。

### 手动配（不想用脚本时）

> 下面命令里的 `python`，源码版指你本机的 Python；
> 便携版指 `<解压目录>\runtime\python.exe`，两者等价。

**WorkBuddy** — 规则放用户级 `MEMORY.md`（跨工作区生效）：

```bash
python scripts/sync_auto_inject.py --append-to \
  "C:\Users\<你>\.workbuddy\user-<id>\MEMORY.md"
```

**Codex / ChatGPT 桌面** — 规则放项目根 `AGENTS.md`，MCP 配置在 `~/.codex/config.toml`：

```toml
[mcp_servers.context-table]
command = 'D:/Python/python.exe'
args = ['D:/context-table/server/main.py']
env = { CONTEXT_TABLE_PATH = 'D:/path/to/memory-table.md' }
```

**DeepSeek Harness** — MCP 客户端是内置的，只在 `cordis.patch.yml` 里加一条即可（`serverName` 用下划线，见 `docs/USAGE.md`）。

**豆包**（⚠️ 未实机验证）— 支持自定义连接器，但**没有配置文件**，只能在界面里手点（约 3 分钟）：

```
侧边栏「技能·连接器·伙伴」→ 新建自定义连接器 → 传输类型选 STDIO
命令   <安装目录>\runtime\python.exe
参数   <安装目录>\server\main.py
环境变量 CONTEXT_TABLE_PATH=<你的表路径>\memory-table.md
```

完整步骤和三个坑见 [`adapters/doubao/INSTRUCTIONS.md`](adapters/doubao/INSTRUCTIONS.md)。

### 日常

**什么都不用做。**

正常聊天，模型在回答末尾带一行：

```
已记：定了 ×1（工具）
```

觉得记错了就说「那条改成 X」。想看表里有什么就说「读一下记忆表」。

## 五个工具

| 工具 | 作用 | 成本 |
|---|---|---|
| `brief()` | 底表 + 最近 3 天 + 未完成待办 | ~500 token |
| `search(query)` | 关键词检索，零命中回退全文 | ~800 token |
| `read(topic)` | 按话题读 | ~3000 token |
| `remember(...)` | 追加一行（重复拦截、校验、加锁、备份） | 0 |
| `prune(...)` | 报告；两个开关都开才执行归档 | 0 |

**结构和撤销走命令行，不占工具位**——模型不会主动"检查格式"或"撤销自己刚写的"，占着只会增加选错的概率。

```bash
python server/main.py validate --table <路径>
python server/main.py undo --table <路径>
```

## 做不到什么

**一、不是每轮都读，但实测比预期稳。**
规则靠自动加载的文件注入，模型看不看得见是确定的，遵不遵守是概率。
实测（2026-11-17，Windows，同一台机器）：

- **WorkBuddy**：说一句有结论的话，它自己判断并调 `remember`，末尾报「已记：xxx」
- **Codex / ChatGPT 桌面**：先 `brief` 读摘要 → 再 `search` 检索 → 最后 `remember`，三步在界面上都能看到
- **DeepSeek Harness**：5 个工具注册成功，同样会主动调，不用开口

**但这是模型判断，不是系统保证。** 长对话后半段、话题突然切换时仍会漏。
漏了你不会收到错误——只会发现末尾没有「已记」那行。100% 需要 pre-turn hook，四个平台都没开放。

**二、只能减少事实型幻觉。**
记错人名、记错时间、记错决定——这些能防。推理错、算错、理解偏了，它管不了。

**三、不能跨设备自动同步。**
表是本地文件。放网盘目录可以，但两台设备同时写仍可能冲突。

**四、中文检索靠 2-gram，不解同义词。**
问“政策原文”，表里写“政府文件”，没有别名就对不上。

**五、权限开太大反而让工具失效。**
Codex 的 `Full access` 模式会禁用审批请求，导致需要审批的 MCP 工具直接失败——模型会改用文件编辑绕过，绕过时没有锁、没有备份。要用 `Ask for approval` + 工具级 `Always allow`。

**六、客户端升级可能悄悄让配置失效。**
DSH 的 `cordis.patch.yml` 里，新增插件必须写成 `- insert:` 包裹的形式；直接写 `- id:` 会被当成“覆盖已有条目”，id 不存在就整条丢弃——**应用照常启动，工具一个都不出现，界面上没有任何提示**。这类坑只有在日志里才看得见。

## 为什么是 Markdown

- 你能打开它、读它、改它、删它
- 备份 = 复制文件
- 换工具不用导出导入
- 出问题能一眼看出哪行错了

**它不新，也不聪明。这正是它能被信任的原因。**
